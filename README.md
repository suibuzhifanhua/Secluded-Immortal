## 1. 这是什么

单文件、零依赖的中文修仙**文字放置**游戏：整个游戏就是 [`仙界闭关小能手.html`](仙界闭关小能手.html)（约 420 KB，一段样式 + 一段游戏逻辑 IIFE + 一段本地助手 IIFE），双击即在浏览器运行，无需构建、无需服务器、断网不影响任何核心功能（只有"大模型助手"需要本机模型服务）。

- **主题**：你是太虚门一个最下等的杂役，偶然拾得一只**只藏不显**的聚宝盆，从此走凡人流苦修路线——攒灵石、修功法、渡劫、飞升，直到入神界封号。
- **玩法骨架**：点击修行/探索 → 突破（17 境 × 9 层）→ 解锁 50 个子系统 → 卡层时转世重开此生（带跨世资产）→ 混元九层后飞升进入神界终局阶梯。
- **一句话定位**：一个"数值与反馈都被关卡盯着"的挂机游戏——所有产出的总开关（全局倍率 = 24 项乘数连乘）在界面上可读、在测试里可证。

## 4. 核心循环

```
修行/探索 → 灵石 + 修为 → 建建筑 · 淬属性 · 炼丹 · 法宝 · 道场 → 突破（层满跨境）
     ↓                                                    ↓
 卡层（缺灵石/缺修为）                       化神起可【转世】 · 混元九层可【飞升】
     ↓                                                    ↓
 攒资源、换路线（道统/姿势）        转世：带气运/祝福/天命重开此生，起点更高
                                                     飞升：凝秩序 → 晋位阶 → 神域道场
                                                              ↓
                                                    【封号神帝 · 通关此界】→ 继续转世刷长线
```

**寿元**是这条循环的隐性计时器（内部"1 秒 = 1 日"，界面上"寿元告急"有两次警告：耗尽八成、只剩 5%）。**寿元耗尽不是游戏结束**——会自动碎丹转世并随机带走一条轮回祝福；延寿丹每瓶再加 100 年缓冲。

| 秘境花费 | `档位价 × 2^境界`（翠屏山 0 / 凤鸟血潭 200 / 天棺神墓 1000） |
| 天劫供奉 | `floor(5000 × 2^境界)`，冷却 3600s，上限 10 枚劫印，每枚全局 +2% |
| 神格晋阶香火 | `floor(400 × 3.2^当前阶)` → 400 / 1280 / 4096 / 1.31万 / 4.19万 / 13.4万 / 42.9万 / 137万 / 439万 |
| 喂灵兽 | 狐 `100 × 2^等级`（25 级封顶）；白虎 `300 × 2^等级`（20 级封顶） |

### 5.2 战力（斗法与石台都拼它）

```
power = 1.6^境界 × 100
      × (1 + 2%·肉身 + 2%·神识 + 1%·魂魄 + 2%·道心)
      × (1 + 5%·功法阶)
      × (1 + 4%·狐等级 ×进化?1.5 + 3%·白虎等级 ×进化?1.5)
      × (1 + 1%·大道总层)
      × (1 + 法宝战力占比)
      × (1 + 2%·结缘数 + 1.5%·劫印) …
```

### 5.3 突破成功率

- 1~8 层：**必定成功**。
- 第 9 层（巅峰）跨境：`clamp(1 − 4%×境界 + 2%×min(道心,20) + 2%×min(护名,5) + (梁画秋?+3%) + (静纹?+1%) + 天命加成 + 四纹共鸣加成, 50%, 100%)`；已是最后一境时恒为 0（无路可走）。
- 失败惩罚：扣修为（初始版本 −15%，现按境界计）。

### 5.4 离线

- 上限 **8 小时**（28800 秒），超出部分不结算——把系统钟拨快一年也仍然只给 8 小时（实测过）。
- 效率 `0.5 + (苏真真结缘 ? 0.10 : 0) + 道统修正`。
- tick 100ms、自动存档 15s、关页面前存档；后台标签页被浏览器节流到每分钟一次时，**走的是同一条日课 / 周愿 / 支线过期分支**（这条曾是缺陷，已修）。

## 8. 全局倍率的封顶史（数值膨胀控制）

所有产出的总开关 = **24 项乘数连乘**（`GM_PARTS`，「修炼产出」面板有一行实时读数）。主梯不设额外的顶：境界 `×1.8/境`（第 16 境 = ×12144）、神格 `×1.25/阶`、道场（×1 → ×110）——它们的顶由表长本身给。

**跨世累积的五条曾经无上限**，是长期膨胀的主因。第五十一轮（用户授权方向为"膨胀不要太快"）给它们加了膝点与封顶：

|---|---|---|---|---|
| 气运 | +10%/点（≤15） | +2%/点 | ×3 | 8h 终点 ×5.00 |
| 转世 | +50%/世（≤6） | +15%/世 | ×8 | 89 世 ×45.5 |
| 轮回祝福 | +5%/叠（≤10） | 不再叠加全局 | ×1.5 | bowl×28 → ×2.40 |

膝点全部落在"头几个时辰 / 头几世就能拿到的量"之下，所以**前期手感一字未动**。实测 A/B（把封顶逐字还原成旧线性式，两侧各跑 4 次 8 小时代打，比的是区间不是单次）：

- 首次抵达混元：**35.4 → 50.8 游戏分**（两组区间不重叠，约 1.43×）；
- 终点全局倍率中位：**2.678×10¹⁰ → 2.528×10⁸**（约 1/106）；
- 168h / 89 世代打里，`转世` 钉在 ×8.00、`气运` ×3.00、`祝福` ×1.50。

## 9. 助手代打与本地大模型

顶部页签 **「大模型助手」**（面板标题「大模型助手 · 闭关顾问」），分四卡：模型接入 / 参数 / 自动闭关 / 剧情生成。

- **接入**：本机 Ollama `/api/chat` + `/api/tags` 健康检查，`think:false`（思考模型会吃光预算），超时 + 退避重试（默认 2 次）。
- **决策**：模型输出严格 JSON，动作过白名单 + 可执行集合校验（`extractJSON` 会剥代码围栏与夹带文本）。
- **兜底**：模型不可用 30s 内自动走 `ruleAction` 贪心（日常 > 突破 > 建造 > 属性 > 探索 > 修炼），**游戏照常推进，不需要模型也能玩**。
- **剧情**：event / npc / quest 三类，模型只决定"发不发奖励"，**数额一律由游戏按境界与全局倍率定标**（`scaled()` / `storyReward()`），支线时限钳在 5~60min；模型不可用时降级为内置佚文。
- **性格三档**：苟道 / 中道 / 搏命——只是"胆量旋钮"（敢不敢渡劫、敢不敢深入），不改任何数值规则。
- **姿势预设**：三套内置（苟道 / 中道 / 搏命）+ 「存我这套」（把你当前的开关组合存成第四套）。
- 配置独立存 `jxp_assist_cfg`，"重置游戏"不清空它。
- 日志只记模型真实输出：**没有 JSON 就不冒充"模型决策"**，`_e2e` 还会识别"陈旧回复"并诚实记 SKIP。

## 10. 新手路线建议

1. **第一天**：点修行 + 探索，攒够就突破；灵石优先灵田 → 药圃（筑基）→ 闭关洞府（金丹）；每天把三桩日课偿掉拿全勤（+20 香火 / +10 令）。
2. **第一周**：别忘了周愿的进度是**差分值**——本周从快照之后做的事才算数（当前已知缺陷见 §13：新档第一周这条线是坏的）。把贡献喂宗门，职位每阶全局 +2%。
3. **筑基**：选**道统**（这是本作唯一真正的"取舍"），换派有冷却与因果代价；打天骄拿首胜 → 大还丹丹方。
4. **化神**：营建炼丹房；从这里开始可以**转世**——第一次转世是长线真正的起点（气运与祝福从此滚起来）。
5. **元婴 ~ 大乘**：道场一路开辟（×1.6 → ×5），万宝楼学会"买信息"（盲买是零期望），洞窟深入按"层数递增 / 风险步进 0.04"自己算该在哪层收手。
6. **仙界**：石台宝库五料优先**道韵**（全局 +1%/阶，封顶 50）与**气运结晶**；攒 36 枚秩序准备飞升。
7. **神界**：位阶香火 `400×3.2^n` 涨得极快，先把器灵里 **聚宝财灵（+12% 全局）** 当成长期目标；神域三处道场是终局倍率的大头。

## 11. 界面与操作

- **模块胶囊**：顶部 7 组入口（修行 / 终局 / 日常 / 资源 / 伙伴 / 挑战 / 远方），窄屏（≤1023）下它们是"换模块"而不是"滚过去"，一次只看一个模块（实测手机页高从 13154px 降到 2912~3051px），末尾「全 展 开」一键回到旧行为；偏好存 `jxp_grp`（不进存档）。**宽屏一律全部展开，只是滚动定位。**
- **页签**：底部页签包含成就簿、典籍（48 条，分 7 组 + 顶部跳转）、大模型助手等。
- **可点的地方真能点**：前程卡每一行都跳转，成就行会闪两下（这条有反向覆盖关卡盯着：任何挂了 `onclick` 的节点都必须在名单里或被写明豁免理由）。
- **只读表不骗人**：算不出百分比的成就界面不硬凑；连续全勤"只是记账与展示，一天额外奖励都没有"这句话也写在典籍里。
- 布局实测：280 / 320 / 390 / 560 / 768 / 1024 / 1440 / 1920 全档 **横向溢出 0**；间距令牌随屏宽单调不减（有断点覆盖自检）。

## 12. 开发与测试约定

**改这个单文件产品的方法（沿用 51 轮积累）**：

1. 写一次性补丁脚本（`_rNNN.js`），用 `rep(锚点原文, 替换文本, 标签)`；**每个锚点必须恰好命中一次**，否则整个补丁中止且不写盘；替换在末尾一次写出；打完即删脚本。
2. **关卡常驻，不要删**。本机若无独立 node，可用 Qoder 自带 exe 当 node：`export ELECTRON_RUN_AS_NODE=1 && "<Qoder CN.exe 路径>" _smoke.js`。

| 关卡 | 它保证什么（规模都是实测） |
|---|---|
| `_chk.js` | 抽出 HTML 里的脚本做语法检查（约 288K 字符，改 JS 第一步） |
| `_smoke.js` | **1386** 条断言：日课 / 周愿发放对拍、倍率膝点与封顶、空洞表检测、存档字段、桥接口行为 |
| `_struct9.js` | **38** 条静态检查：间距令牌随屏宽单调不减（并自证"看得见"）、每个分组面板都有真归属、折叠类只能写在 ≤1023 那一支、`ACH_PROG` 未被截断 |
| `_panel.js` | 240 组局面（随机 + 边界各 120）扫描渲染出的脏字符串（undefined / NaN / 负数） |
| `_roundtrip.js` | 存档深拷贝往返 + 坏档 / 老档兼容（曾抓到"坏档会永久 brick 游戏"） |
| `_uiparity.js` | 204 颗 `onclick` 全覆盖 + 反向覆盖 + 豁免必须写明理由并存在；抓"按钮亮着但游戏拒绝" |
| `_parity.js` | 400 组随机局面、累计 **24908** 次尝试：`availableActions` 与游戏守卫同判同拒 |
| `_ach.js` | 151 条成就在最大态 / 对偶档都可达；122 条 `ACH_PROG` 门槛两侧夹逼（差一格必须不成立） |

| `_serve.js` | 只监听 127.0.0.1 的临时静态服务器，供同源 iframe 在多档宽度量布局；用完即停 |

## 13. 已知缺陷与未完成

截至 2026-11-06，下列各项均已登记为任务，尚未修：

| 编号 | 问题 | 实测依据 |
|---|---|---|
| #36 | **新档第一周的「本周三愿」恒 0**：`ensureState` 建周时写 `snap:null`，而周愿进度是"当前 − 周初快照"，快照缺失就用"读的那一刻"兜底 → 当前减当前永远 0。做满目标也领不到奖；坏的正好是**开局那 7 天**（此后每逢真实周界自愈） | 新档首周设目标 12 次、真做 30 次（`S.breakN=30`）→ `weekProg=0` 不可偿；跨周后同样 30 次 → `prog=30` 可偿 |

| #37 | **`travel`（前往最高道场）永远不可做**：开辟新道场时已自动搬入，该动作成了死键 | `act.unlock(i)` 连开 6 处后 `S.area` 自己 0 → 6 |
| #38 | **没有渐进开放**：50 个在册系统里 **28 个在炼气一层（开局 0.1min）就全部可做**；新号首屏在 1440 宽度是 **30/30 面板全摆着**（含「神界 · 飞升 终局阶梯」「天劫试炼」「无尽石台」「天骄榜」）；另有 4 个终局系统（器灵觉醒 / 灵兽进化 / 声望兑换 / 本命纹洗练）在 89 世代打里**从未可做** | `_sim` 的「系统首开阶梯」常驻打印 + 清空存档后的同源 iframe 实测 |
| — | 主线第 13 章名「打胶工」与其余 15 章的四字章名风格不齐（内容是有意的自嘲，标题像占位） | `CHAPTERS[12]` |
| #34 | 「远方」二十座志向折叠区（把终局志向做成可折叠的一组） | 待做 |

关于 #38 的提议方案（**数值一处不动，只改"什么时候摆到眼前"**）：按境界带做"未开先隐"——修真界只留修行 / 建筑 / 行囊 / 日志 / 道场 / 日课，灵界引入石台 / 洞窟 / 宗门 / 道统 / 弟子，仙界引入法宝 / 洗练 / 器灵 / 红颜 / 天劫，神域（飞升后）引入神格 / 秩序 / 神珠 / 天命；每带第一次出现时打一句「新通道：…」，前程卡留一行「下一境解锁 X」，把等待变成期待。属于设计改动，**需要明确授权**。
